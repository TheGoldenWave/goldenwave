## 1. 背景与目标

v0.1 给了用户一套规范的**空骨架**（init 后得到目录 + SPEC）。但"往哪填、怎么填"仍全靠人，与"又一个 Obsidian 模板"区分度不足。

**路由器要解决的核心问题**：用户把任意原料丢进 `inbox/`，系统**自动判断它属于哪一层、渲染成合规页面、并安全写入**——把 goldenwave 从"结构标准"变成"会自己长的知识系统"。

**北极星**：inbox 里的一条原料，经路由器处理后，正确落到 事实(L1)/知识(L2)/人格(persona) 的合规页面，且全程可审计、可回退。

## 2. 设计原则（不破 SPEC 红线）

1. **半自动，不全自动**：agent 判断 + 人确认。高敏/低稳定一律先进草稿。
2. **按风险审计**：允许长期保留的摘要可进入 Git；local_private/ephemeral 内容不进入任何 Git 历史，日志不得泄露高敏正文。
3. **三维分流**：严格区分 事实/知识/人格，不混淆。
4. **不确定就问**：路由置信度低 → 进 `inbox/_pending/` 待人裁决，绝不静默入库。

## 3. 流水线（借 OpenHuman capture→score→render→inject）

```
inbox/原料
  │
  ├─① capture        收集 + 标准化
  ├─② route          L1 / L2 / persona / Social Memory node-or-edge / 丢弃
  ├─③ score          证据 + 稳定度 + 敏感度 + policy tags + storage class
  ├─④ merge-check    Person/Collective 只生成合并候选
  ├─⑤ consent-check  分别检查 store/summarize/suggest/share/remote_model
  ├─⑥ redact         删除超用途字段，隔离高敏原文
  ├─⑦ render         按目标层与 storage_class 渲染候选
  ├─⑧ user-confirm   高敏/第三方/推断/合并必须确认
  └─⑨ inject         原子写入对象、边、索引与安全日志
```

### 各步细节

**① capture**：支持 .md/.txt/链接/对话片段。输出统一中间格式 `{text, source, captured_at}`。

**② route（核心分类器）**：一个 agent prompt，对每条原料判定：
- 维度：是"此刻为真的事实" → L1（再判九域）；"可复用知识" → L2（再判八类）；"我怎么想/说话" → persona。
- Social Memory 路由规则已完成设计，但不属于近期通用摄入实现；进入 Phase 4 前只保留通用第三方数据与存储等级门禁。
- 输出 `{layer, target, confidence, reason}`。
- confidence < 阈值 → `_pending/`。

**③ score**：
- 证据分级：原话=verbatim，成稿=artifact，他人转述=impression。
- 稳定度：一次性 vs 长期；决定 refresh 周期。
- 敏感度：L0–L3，决定是否进 git / 是否脱敏。
- policy tags、用途授权和 storage_class 与敏感度正交；L3 Social Memory 默认 local_private。

**④–⑥ merge / consent / redact**：身份只生成合并候选；按用途授权决定可处理字段；删除超出用途或日志允许范围的内容。

**⑦–⑨ render / confirm / inject**：
- 高稳定 + 低敏 + 高置信 → 直接写入对应目录。
- Social Memory、高敏、第三方、推断和合并候选 → `inbox/_pending/` 草稿，附路由决策卡，等用户 confirm。
- 写入后：更新 `wiki/<type>/index.md` 或 `profile/<域>/index.md`、补双链、追加 `.kb/log.md`。
- 写入失败必须回滚对象、边和索引，不留下悬空引用。

## 4. 交付物

- `skills/goldenwave-ingest/SKILL.md` — 路由器 skill（挂 agent 调用）
- `goldenwave ingest` — experimental 统一 CLI 入口（扫 inbox / 接收文件 → 产候选）；内部可以复用 Skill 或脚本，但不把 `route.py` 文件名作为公共合同
- `goldenwave validate / doctor` — 验证 Contract envelope，并诊断 Knowledge Base 目录、版本和权限
- `inbox/_pending/` 草稿区约定 + 决策卡格式
- `social-memory-patch/v0.1.0` Schema、合法/非法 fixture 与权限/撤回测试向量（Phase 4 候选，不是近期交付）
- SPEC L3 标记 v0.2 进行中，并区分已完成 Skill / `_pending/` 与待完成 Contract / CLI / validator

## 5. 验收标准

1. 投 10 条混合原料（含事实/知识/人格/敏感），路由准确率 ≥ 80%，敏感项 100% 进草稿不直接入库。
2. 每次路由在 `.kb/log.md` 留可读决策记录。
3. 错误路由可按存储等级回滚：git_tracked 使用 Git revert，local_private 使用受审计的本地操作日志恢复；ephemeral 不产生正式写入。
4. 不依赖任何云服务即可跑（本地模型亦可）。
5. 同名、同公司或同群聊不会触发静默身份合并，错误自动合并数为 0。
6. 第三方高敏内容、推断和缺少授权的候选 100% 不直写正式层。
7. 未授权 share、remote_model、自动发送和导出事件为 0。
8. 撤回会传播到正文、索引、缓存、简报和反向引用，测试向量 100% 通过。
9. 需要保证硬删除的数据不会进入 Git 历史；对已入 Git 的数据不得虚假宣称硬删除。
10. `.private/` 缺少 ignore 或 local_private 文件已被 Git 跟踪时，validate/doctor 必须 fail closed。
