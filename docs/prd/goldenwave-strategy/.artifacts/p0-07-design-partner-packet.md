# P0-07 设计伙伴协议与访谈材料包

本材料包只覆盖外部设计伙伴泳道的准备工作，不代表任何邀请已发出，也不代表已获得外部知情同意。P0-08 只有在用户完成实际引荐或发送邀请后才能转入 `waiting_external`。

## 目标

- 为最多 `3` 名候选设计伙伴准备统一、低敏、可复核的外联材料。
- 让用户只承担 Agent 不能代理的真实引荐动作。
- 保证访谈不读取对方私有正文，不收集与 Phase 0 目标无关的敏感信息。

## 候选画像

优先候选应同时满足以下条件：

1. 正在同时使用至少两个 Agent 或 AI 工作流。
2. 已有 Markdown、Obsidian、项目仓库或同类长期资料资产。
3. 明确在意来源、权限、确认、回滚或跨 Agent 复用问题。
4. 能接受一次 `30-45` 分钟的概念/安装访谈。

不适合作为本轮设计伙伴的对象：

- 只把 Agent 当一次性聊天工具、没有长期资料资产的人；
- 无法接受本地优先、审计与显式确认约束的人；
- 需要 Agent 直接接触其私有正文或生产数据的人。

## 用户发送邀请文案

以下文案由用户本人发送，Agent 不直接对外联络：

```text
我在验证一个本地优先的个人上下文治理工具 GoldenWave，目标是让同一份个人上下文可以被多个 Agent 安全复用，而不是反复在不同工具里解释自己。

我想邀请你做一次 30-45 分钟的概念/安装访谈。访谈不会读取你的私有正文，也不会要求你提供生产数据；我们只讨论你的工作流、上下文痛点，以及你是否认同“治理一次、任意 Agent 复用”的问题定义。

如果你愿意参与，我会先发一页知情说明，确认你同意后再约时间。你可以随时中止，也可以要求不保留任何可识别记录。
```

## 知情同意要点

在访谈开始前，用户需要逐项明确并得到对方同意：

1. 访谈目的是验证问题与安装/接入路径，不是销售或公开案例宣传。
2. 本轮不读取对方私有正文，不索要账号密码、API Key 或生产仓库访问权。
3. 只记录匿名 `partner_id`、日期、是否同意、核心问题是否成立、关键阻塞和后续动作。
4. 纪要可随时终止，且默认不包含姓名、公司、仓库链接和原始敏感片段。
5. 对方可要求删除未汇总的访谈记录。

建议的口头确认句：

```text
这次访谈只会记录匿名结论，不读取你的私有正文，也不要求任何账号授权。你可以随时停止；如果你同意，我会只保留匿名问题结论和日期。这样可以吗？
```

## 访谈 Rubric

### A. 现状与问题确认

1. 你现在会在几个 Agent 或 AI 工具之间切换完成同一类任务？
2. 你是否经常需要重复解释自己的背景、项目状态或偏好？
3. 这些上下文目前主要散落在哪些地方？

### B. 风险与治理需求

4. 你最担心的是事实混淆、来源不明、私有内容泄露，还是 Agent 未经确认写入？
5. 如果一个工具要求所有正式写入都显式确认、可回滚，你觉得这是必要约束还是额外负担？
6. 你是否需要区分可进 Git、仅本地私有、临时缓存三类存储等级？

### C. 安装与接入可行性

7. 你现有资料是否主要是 Markdown/仓库/本地文件，可接受只读诊断先于自动迁移吗？
8. 如果第一步只提供 `init`/`doctor`/只读 adopt inventory，你是否愿意先试用？

### D. 价值判断

9. “Govern once, use with any agent” 是否准确描述了你要解决的问题？
10. 如果不准确，缺的那一块是什么？

## 访谈结论记录模板

每位设计伙伴在 P0-08 只回传以下脱敏字段：

```yaml
partner_id: dp-001
date: 2026-07-27
introduced_by_user: true
consent_status: granted | declined | pending
core_problem_confirmed: yes | no | mixed
current_agent_count: "2+ | 1 | unknown"
primary_pain_points:
  - repeated_context
  - provenance
  - unauthorized_write
phase1a_willingness: yes | no | later
notes_summary: >
  匿名总结，只保留问题结论、阻塞和下一步，不记录私有正文。
next_action: schedule | follow_up | stop
```

禁止写入：

- 姓名、公司、邮箱、仓库 URL、账号标识；
- 私有正文摘录；
- 未脱敏的业务、财务、健康或亲友信息。

## P0-08 进入条件

P0-08 只能在以下任一真实动作发生后推进：

1. 用户已向候选设计伙伴发出邀请并可提供日期；
2. 用户已完成实际引荐并可提供候选匿名编号与状态。

若仅完成本材料包而未发生真实外联，则 P0-08 保持 `todo`。

## 本材料包完成标准

- 候选画像、邀请文案、知情同意和访谈 rubric 已冻结。
- 匿名证据字段已定义，可直接进入 P0-08。
- 无需额外产品决策，不改变外部 Gate 标准。
