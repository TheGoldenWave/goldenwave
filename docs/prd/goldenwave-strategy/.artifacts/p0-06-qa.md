# P0-06 QA Protocol

## Can Start Batch

P0-06 can start the `20` single-response `phase0-human-proxy` runs because the frozen suite is still `preregistered`, representativeness evidence is `confirmed`, and the preregistered run manifest already passes preflight:

```bash
ruby tests/specs/phase0/p0-baseline-preflight.rb \
  --suite tests/specs/phase0/real-dogfood-tasks-v0.1.yaml \
  --runs tests/evidence/phase0/run-manifests/p0-v0.1-run-ids.yaml
```

Expected result:

```json
{"status":"ok","suite_id":"phase0-real-dogfood-preregistration","suite_status":"preregistered","evidence_status":"confirmed","run_ids":20}
```

## Execution Rules

For each preregistered `run_id`:

1. Load exactly one frozen task from `tests/specs/phase0/real-dogfood-tasks-v0.1.yaml`.
2. Supply only the frozen sanitized sources named in `input_manifest.source_ids`.
3. If the task carries `input_manifest.confirmation_ref` and `confirmation_digest`, pass through the frozen bound values from the suite and never ask the owner again.
4. Present `frozen_prompt` verbatim.
5. Record exactly one visible agent response and score only that first response.

Mark the run `invalid` if any of the following happens:

- forbidden real input is read
- fixture or snapshot revision differs from the frozen suite
- the evaluator improvises criteria outside the six frozen assertions
- the agent is given a second answer attempt, owner reprompt, or reviewer reframe

## Private Raw-Output Layout

Raw artifacts stay outside Git under:

```text
.private/goldenwave/baselines/p0-v0.1/
├── raw/<run_id>.json
└── reviews/<run_id>.json
```

Minimum local-private records:

- `raw/<run_id>.json`: suite/task/run metadata, source IDs, timestamps and the first visible response
- `reviews/<run_id>.json`: local reviewer sheet with per-assertion decisions and failure rationale
- optional transcript may be stored separately when tool-level replay is required

Rules:

- no raw owner values in repo
- no `.private/` paths inside repo scorecards
- no L3/private source body text under `tests/evidence/`
- every preregistered run must have exactly one raw record and one review record

Recommended opaque evidence refs for repo metadata:

- `capture_<task_id>`
- `response_<task_id>`
- `review_<task_id>`
- optional `transcript_<task_id>`

## Repo Scorecard Metadata Schema

Repository scorecards should live in `tests/evidence/phase0/run-manifests/` as a top-level YAML array. Each entry must contain exactly these allowlisted fields:

- `suite_id`
- `task_id`
- `run_id`
- `agent`
- `timestamps`
- `assertion_results`
- `error_class`
- `correction_cost`
- `evidence_refs`

Nested contract enforced by QA validator:

- `timestamps`: exact keys `started_at`, `first_response_at`, `scored_at`, `ended_at`; all RFC 3339; monotonic
- `assertion_results`: exactly 6 ordered `{dimension,result}` items matching the suite assertion order; `result` in `pass|fail|invalid`
- `error_class`: slug only; must be `none` when all 6 assertions pass
- `correction_cost`: exact keys `first_response_turns`, `reviewer_reframes`, `repeated_explanations`; single-response runs require `first_response_turns=1` and `reviewer_reframes=0`
- `evidence_refs`: `3..4` opaque refs only; must include `capture_`, `response_`, `review_`; optional `transcript_`; no path separators or dot-prefixed refs

## Observed Baseline Result

- `20` runs reviewed; `0` fully passing, `0` invalid.
- `96/120` assertions passed and `24/120` failed.
- Provenance attribution failed in all `20` runs and is the dominant baseline gap.
- Fact-value assertions failed in `3` runs; workflow-fit failed in `1` run; freshness and permission each passed `20/20`.
- Observed first-response metadata has a median of `14.5s`. Five runs share one batch-level `65s` boundary, so this batch supports aggregate baseline observation but not precise per-task latency comparison.

P0-06 measures the pre-product starting point; task failures are valid baseline findings and must not be repaired with second responses. Completion means all frozen runs were captured, independently scored and validated, not that the current manual proxy met the future product Gate.
