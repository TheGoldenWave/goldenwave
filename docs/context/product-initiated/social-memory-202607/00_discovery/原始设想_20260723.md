# Social Memory 原始设想

## 起点

GoldenWave 已在 L1 `profile/04-social/` 为亲友档案、职场关键人和人情账预留位置，但尚未定义“人”“组织”“关系”和“互动”如何成为可治理、可审计的长期上下文。

## 用户确认

1. Social Memory 的核心目标是**帮助我维护真实关系**，整个系统围绕“我”推进。
2. V1 同时记录“人”与“组织关系”，两者相辅相成。
3. 家庭、朋友圈、项目组、公司和社群统一抽象为广义 `Collective`，再通过类型区分。
4. 普通关系事实默认本地高敏保存；原始聊天默认不长期保留。
5. 第三方敏感属性和人格推断需要明确授权；Agent 不得自动对外分享。

## 初始产品命题

Social Memory 不是联系人列表、企业 CRM 或社交监控系统。它是 GoldenWave 中以 `self` 为锚点的个人关系上下文层，帮助用户：

- 记住人与组织之间对自己有意义的联系；
- 在互动后沉淀事实、承诺和下一步；
- 在联系前恢复必要上下文；
- 发现陈旧、冲突和待确认的信息；
- 始终由用户决定是否记录、联系、分享或删除。

## 已识别的核心矛盾

GoldenWave 的 Git 审计原则与第三方数据的可撤回、可硬删除要求存在冲突。Social Memory 必须引入独立于敏感度的存储等级：可跟踪摘要、本地私有内容和临时原始材料。需要保证硬删除的数据不得进入 Git 历史。
