# 产品简报 — GoldenWave Social Memory

## 发现来源

来自 GoldenWave 五层模型的产品推演：当前 L1 已包含 `04-social`，但只有目录归属，没有关系对象模型、隐私生命周期和可执行工作流。用户确认 Social Memory 应以“帮助我维护真实关系”为目标，同时覆盖人与广义组织关系。

## 核心假设

我们相信，当个人 AI 能以用户为中心保存最少但可靠的关系上下文，并在联系前后提供可控辅助时，用户会更容易履行承诺、延续重要关系。验证方式不是采集更多数据，而是衡量关系简报是否有帮助、待跟进事项是否完成，以及是否发生隐私越界。

## 功能概要

V1 将 `Person` 与 `Collective` 作为一等关系对象，通过 `Relationship`、`Affiliation` 和 `Interaction` 连接，并以 `Commitment` 承载用户需要履行的后续动作。系统支持创建对象、记录互动、生成联系前简报、核验陈旧事实、处理合并与撤回。

Agent 只提供整理、提醒和草拟能力，不自动发送、分享、同步或推断第三方敏感属性。

## 预期效果

| 指标 | 当前值 | V1 目标值 | 衡量方式 |
|------|-------|-----------|---------|
| 联系前恢复上下文耗时 | 无标准 | 不超过 30 秒 | 可用性测试 |
| 关系简报有帮助率 | 无标准 | >= 70% | 用户本地反馈，可选汇总 |
| 已确认承诺按期完成率 | 无标准 | >= 60% | 本地状态统计 |
| 未授权分享或自动发送 | 无标准 | 0 | 验收测试与审计日志 |
| 未授权敏感推断入库 | 无标准 | 0 | 安全测试向量 |
| 静默错误合并 | 无标准 | 0 | 身份消歧测试集 |

默认不启用遥测。产品指标只在本地计算，除非用户显式选择分享匿名结果。

## 风险与依赖

- Git 历史无法天然满足第三方数据硬删除，需要存储等级与 purge 语义。
- 冷启动录入过重会降低持续使用率，应允许从一次互动渐进建档。
- 不保留原始聊天会增加摘要失真风险，需要来源引用和核验机制。
- `Collective` 容易滑向组织知识库，必须限制为“与我相关的组织关系上下文”。
- V1 依赖 Social Memory Schema、治理扩展和 ingest 安全门禁先行定义。
